# 开发、运行、测试与打包

## 1. 环境要求

当前项目以 Windows 为主要目标，尤其是批处理、HTA 和单 EXE 部分。Streamlit 主线本身可在其他桌面系统运行，但 `launcher.py` 的打包与进程体验主要按 Windows 设计。

建议使用独立虚拟环境。当前依赖清单没有锁定完整传递依赖，也没有声明 Python 版本；审阅环境使用 Python 3.14，单元测试可通过，但不代表所有 Streamlit/PyInstaller 组合都正式支持该版本。

安装现有运行与打包依赖：

```powershell
python -m pip install -r requirements_exe.txt
```

如需运行测试和 Excel 转换，还需要：

```powershell
python -m pip install pytest openpyxl
```

建议后续拆分：

```text
requirements.txt
requirements-dev.txt
requirements-build.txt
```

或改用 `pyproject.toml` 与锁文件。

## 2. API 配置

推荐通过环境变量，不把 Key 写入仓库：

```powershell
$env:LLM_API_KEY = "你的Key"
$env:LLM_API_URL = "https://example.com/v1/chat/completions"
$env:LLM_MODEL = "你的模型名"
```

也可以使用具体提供商变量：

```text
DEEPSEEK_API_KEY
OPENAI_API_KEY
ZHIPU_API_KEY
XAI_API_KEY
```

Streamlit secrets 可提供：

```toml
api_key = "你的Key"
```

当前代码没有仓库内 `.streamlit/secrets.toml` 模板。

## 3. 直接运行

1000 人版：

```powershell
streamlit run app.py
```

全古代 200 人版：

```powershell
streamlit run app_03_mini.py
```

明朝主题版：

```powershell
streamlit run app_03_ming.py
```

对应根目录还有三个中文 `.bat` 入口。应从项目根目录启动，因为人物库和 Prompt 包使用相对路径。

根目录 `旧版.bat` 当前引用 `app_01_01.py`，但文件已经移到 `legacy/`，所以该入口按现有目录结构不可用。

## 4. 运行单 EXE 启动器的开发态

可以直接运行：

```powershell
python launcher.py
```

它会：

1. 把运行时文件复制到 `%LOCALAPPDATA%\GuessHistory\runtime`；
2. 在 8750 起寻找首页端口；
3. 打开浏览器首页；
4. 根据页面选择启动 Streamlit 子进程；
5. 把日志写入 `%LOCALAPPDATA%\GuessHistory\logs`。

关闭主启动器进程后，它会尝试回收已登记的游戏进程。

## 5. 单元测试

运行：

```powershell
python -m pytest -q
```

审阅时结果：

```text
41 passed, 1 warning
```

警告来自 `.pytest_cache` 无法创建缓存路径，不影响断言结果。仓库中的 `.pytest_cache` 状态异常或权限受限，建议删除后由 Pytest 重建；删除前应确认它只是生成缓存。

### 当前测试优势

- 状态阈值边界已覆盖。
- 重置和阶段切换已覆盖。
- 多类关键词检测已覆盖。
- 事实问答收集过滤已覆盖。
- Prompt 关键内容有快照式断言。
- 批量复核切分与回调使用 mock 验证，不消耗真实 API。

### 当前测试缺口

- `call_llm()` 的 4xx、429、5xx、超时、坏 JSON、空 `choices`。
- 三套人物池的精确边界，尤其是明朝版不应追加外部人物。
- JSON Schema 和坏数据处理。
- 多局重开后的消息隔离。
- 猜中、投降、提示计数的完整行为。
- Streamlit 页面烟雾测试。
- `launcher.py` 的接口、并发、端口和进程生命周期。
- 构建后 EXE 的实际启动、资源完整性和离线行为。

## 6. 构建 EXE

现有批处理：

```powershell
.\build_exe.bat
```

等价的核心命令：

```powershell
python -m PyInstaller --noconfirm --clean build_exe.spec
```

预期产物：

```text
dist\GuessHistory.exe
```

### 打包内容

- `launcher.py`
- `frontend/index.html`
- 三个当前游戏入口
- 六个核心顶层模块
- `prompts/*.py`
- 1000 人 Markdown
- 两个 200 人 CSV
- 结构化 JSON
- Streamlit 运行所需的动态依赖

### 构建现状

- 本地已有 `dist/GuessHistory.exe` 和 `build/build_exe/`。
- `build/` 与 `dist/` 被 `.gitignore` 排除。
- PyInstaller 警告文件包含大量可选模块缺失，很多是跨平台或测试依赖，不等同于构建失败。
- `collect_all()` 会把大型库的许多内容一起收集，构建体积和分析时间较大。
- 批处理清理目录名与本地实际 PyInstaller 工作目录不一致。
- 批处理中文已乱码，应重新以正确 UTF-8 或 Windows 批处理兼容编码保存。

## 7. 发布前建议的验收清单

1. 从干净虚拟环境安装依赖。
2. 运行全部单元测试。
3. 验证三套人物池数量分别为 1000、200、200。
4. 扫描仓库与产物，确认没有可用 API Key。
5. 构建 EXE。
6. 在无 Python 的 Windows 测试机上启动。
7. 分别打开三个模式并完成开局、普通问答、提示、重答、猜中和重玩。
8. 更换 API 提供商后确认新进程确实使用新配置。
9. 断网启动，确认首页仍能工作且字体回退正常。
10. 关闭启动器，确认所有 Streamlit 子进程退出。
11. 检查 `%LOCALAPPDATA%\GuessHistory\logs` 中没有凭证或完整敏感请求头。
