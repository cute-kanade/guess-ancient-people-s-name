# 模块与文件说明

## 1. 当前主线 Python 文件

### `app.py`

1000 人版主入口，也是项目直接运行的默认入口。负责 Streamlit UI、API 配置选择、会话消息展示、游戏分支调度和调用核心模块。

### `app_03_01.py`

与 `app.py` 字节级完全相同，是 v3 统一入口的历史命名副本。当前启动器和打包清单不使用它，继续保留会增加修改漂移风险。

### `app_03_mini.py`

全古代 200 人版。使用 `top200_famous_people.csv` 的“人名”列，主题为“中国历史”。当人物库为空时临时退化为“王阳明”。

### `app_03_ming.py`

明朝主题版。使用明朝 CSV 的“简体人名”列，并为缺少结构化数据的 CSV 人物补默认朝代“明”。由于 `people_db.py` 的通用追加策略，当前实际包含 377 人，详见数据文档。

### `config.py`

集中保存默认 API URL、默认模型、温度、重试、超时、批量大小、提示阈值和数据路径，并提供默认 Key 解析函数和 `APIConfig` 数据类。

当前存在两个维护问题：

- `APIConfig` 没有在主线中实际使用。
- `llm_client.py` 又定义了一套相同常量，没有完全复用这里的配置。

### `game_state.py`

包含：

- `GamePhase`：`PLAYING`、`WON`、`SURRENDERED`。
- `GameState`：目标、提问数、阶段、提示历史。
- 提示阈值计算。
- 投降、提示、重玩、怀疑意图的关键词检测。
- 五种规范答案识别。
- 从聊天记录收集事实问答对。

它是当前测试覆盖最完整的模块之一。

### `people_db.py`

定义 `Person` 数据类以及 Markdown、CSV、JSON 加载器。支持：

- 解析 `序号. 姓名`；
- 多编码 CSV；
- MD/CSV 为全集、JSON 为结构化覆盖；
- 按姓名精确查找；
- JSON 保存。

主题人物池和 JSON 的合并语义需要拆分为“只覆盖”和“覆盖并追加”两种模式，否则会污染限定主题。

### `fact_checker.py`

把 `Person` 非空字段转成 Prompt 文本，再追加通用事实核查规则。文件中定义了朝代、性别、身份和头衔关键词，但当前主流程没有根据用户问题使用这些规则进行程序化判断。

因此它目前更准确的定位是“结构化事实 Prompt 注入器”，不是直接回答问题的事实判定器。

### `llm_client.py`

负责：

- 环境变量提供商探测；
- OpenAI 兼容 HTTP 请求；
- Key 空值检查；
- 4xx、429、5xx、超时和连接错误处理；
- 指数退避重试；
- 普通回答；
- 批量历史核查。

没有实现流式输出、异步请求、响应 Schema 校验、全局限流或请求取消。

### `launcher.py`

单 EXE 的真正入口。负责资源释放、本地 HTTP 首页、脚本白名单、Streamlit 子进程、端口、日志、浏览器打开、健康轮询和退出回收。

## 2. Prompt 包

| 文件 | 职责 |
| --- | --- |
| `prompts/persona.py` | 考官角色和游戏目标 |
| `prompts/state.py` | 注入目标人物、提问数和提示状态 |
| `prompts/rules.py` | 限定五种规范答案 |
| `prompts/hint.py` | 根据 Python 已算好的状态选择 blocked/enabled Prompt |
| `prompts/output.py` | 猜中、投降和正常对话格式 |
| `prompts/fact_check.py` | 通用事实核查强化规则 |
| `prompts/recheck.py` | 单条与批量重答 Prompt |
| `prompts/tools.py` | 未来 Agent 工具说明，目前关闭 |
| `prompts/builder.py` | 统一组装系统 Prompt |
| `prompts/__init__.py` | 对外导出接口 |

`prompts/md/` 是 v2 阶段的对应说明文档，整体设计仍有参考价值，但没有完整反映 v3 新增的事实核查、批量重答和结构化人物注入。

## 3. 当前前端与构建文件

### `frontend/index.html`

单 EXE 的启动首页，提供：

- 深浅主题切换与本地记忆；
- 中国和欧洲模式卡片；
- 三个可用 v3 入口；
- API 提供商、Key、URL、模型配置；
- 调用 `/api/launch`；
- 启动状态和 Toast。

它是普通浏览器页面，不依赖 ActiveX。字体通过 Google Fonts 加载，离线时会回退到系统字体。

### `build_exe.spec`

显式收集 Streamlit、Altair、Pandas、PyArrow、NumPy 等依赖以及运行时源码和数据。由于 `launcher.py` 不直接导入游戏模块，这些源码必须通过 `datas` 手动打包。

### `build_exe.bat`

检查依赖、清理旧产物、调用 PyInstaller。文件中的中文已经发生二次编码乱码；命令主体仍以 ASCII 为主，通常还能执行。它清理的是 `build\GuessHistory`，但本地现有 PyInstaller 工作目录为 `build\build_exe`。

### `requirements_exe.txt`

仅包含运行和打包所需的三项顶级依赖，未形成锁定版本或开发依赖清单。

## 6. 历史与仓库杂项

### `legacy/`

保存 v1 和 v2 的 Streamlit 单文件或半模块化实现。它们展示了项目从 DeepSeek 单提供商、硬编码 Prompt，演进到多提供商、Python 状态、事实核查和重答的过程。多份文件仍含历史明文 Key，不应作为可分发入口。

### 根目录 `exe_*.hta` / `exe_*.html`

是多代 Windows HTA/HTML 主页面原型。早期版本使用 ActiveX 和 `WScript.Shell` 直接启动批处理或 Streamlit；v3 版本加入主题和内置凭证混淆。当前单 EXE 使用的是 `frontend/index.html`，这些根目录页面都不在打包运行链路中。

### 两个 Dify YAML

`猜中国古人（1000人版本1.1).yml` 和 `1.2` 是早期 Dify advanced-chat 工作流：

- 生成 1～1000 随机数；
- 知识检索；
- 从文档中抽取人名；
- 写入会话变量；
- 用 DeepSeek 节点回答；
- 通过条件分支处理开局。

1.2 主要修复了目标变量引用、扩充四大铁律并强化提示不重复和投降逻辑。

### `.obsidian/` 与 `.base`

这是作者的 Obsidian 工作区配置。`workspace.json` 中还引用了当前仓库不存在的旧笔记与旧源码，属于本机编辑器状态，不是运行依赖。

### `t`

内容是一次 `git config --list --show-origin` 一类命令的输出快照，包含作者邮箱、本机 Git 路径和远程仓库信息。它不是项目功能文件，且不应长期受版本控制。

### `build/`、`dist/`、`__pycache__/`

是本地生成物，已被 `.gitignore` 排除。审阅时存在 `dist/GuessHistory.exe` 和 PyInstaller 分析文件，但它们不是受版本控制的源码。
